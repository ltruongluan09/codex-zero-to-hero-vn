Làm Codex hiểu cách mình làm việc.

Sau khi tạo được tool đầu tiên, câu hỏi tiếp theo là: làm sao để lần sau Codex hiểu bạn nhanh hơn? Buổi này giúp bạn tạo ba thứ rất thực tế: quy tắc project, thói quen cá nhân và workflow dùng lại.

Tạo AGENTS.md Tạo skill kiểm tra
Lumi Bot dẫn đường Đây là lúc dạy Codex “gu làm việc” của bạn.

AGENTS.md là nội quy, Memory là thói quen nên nhớ, Skill là checklist dùng lại. Không cần học sâu, chỉ cần biết dùng đúng lúc.

Giải thích cực dễ hiểu

1
AGENTS.md

Là “nội quy làm việc” của Codex trong project. Ví dụ: luôn giải thích tiếng Việt, không xóa file nếu chưa hỏi, luôn chạy build trước khi kết thúc.

2
Memory

Là những thói quen cá nhân Codex nên nhớ qua nhiều lần làm việc. Ví dụ: bạn dùng Windows, thích câu trả lời ngắn, ưu tiên app đơn giản.

3
Skill

Là một workflow đóng gói để dùng lại. Ví dụ: trước khi push, kiểm tra Git status, build, test và gợi ý commit message.

Trước khi bắt đầu cần chuẩn bị gì?

🧩 Tool từ buổi 2 đã chạy được

Nếu chưa có tool, vẫn học được. Nhưng tốt nhất là dùng chính project nhỏ bạn đã tạo ở Session 2.

📝 Một vài điều bạn muốn Codex làm theo

Ví dụ: trả lời tiếng Việt, không xóa file bừa, luôn báo rõ đã sửa gì, ưu tiên cách đơn giản.

🧠 Hiểu đơn giản: đây là cách dạy Codex nhớ luật chơi

Không phải học kỹ thuật mới. Bạn chỉ đang viết ra cách bạn muốn cộng sự AI làm việc cùng mình.

Làm theo từng bước

1
Tạo AGENTS.md cho project

Copy prompt ở phần dưới. Codex sẽ tạo một file nội quy để những lần sau làm việc ổn định hơn.

2
Đọc lại nội quy cùng Codex

Đừng bỏ qua bước này. Nếu có câu nào quá kỹ thuật, yêu cầu Codex viết lại cho người mới hiểu.

3
Nhờ Codex đề xuất Memory

Memory giống những thói quen cá nhân. Chỉ lưu điều giúp làm việc tốt hơn, không lưu mật khẩu hay API key.

4
Tạo skill ship-check

Skill này giống checklist trước khi giao bài: xem file đã đổi, chạy build/test, rồi gợi ý commit message.

5
Dùng skill để kiểm tra project

Sau khi tạo xong, hãy yêu cầu: “Dùng skill ship-check kiểm tra project này giúp tôi.”

Prompt tạo AGENTS.mdNội quy project
Hãy tạo file AGENTS.md cho project này để Codex làm việc phù hợp với tôi.

Bối cảnh:
- Tôi là người non-tech
- Tôi muốn dùng ngôn ngữ tự nhiên để tạo và sửa tool
- Tôi muốn Codex tự làm phần kỹ thuật nhiều nhất có thể
- Tôi muốn giải thích ngắn gọn bằng tiếng Việt

Quy tắc cần có:
- Trước khi sửa code, đọc project để hiểu stack
- Không xóa file nếu chưa hỏi
- Không push GitHub nếu tôi chưa yêu cầu
- Nếu app lỗi, tự đọc terminal/log/browser console và sửa
- Sau khi sửa, chạy build/test nếu có
- Cuối task, báo cáo file đã sửa, lệnh đã chạy, build/test, commit nếu có

Hãy viết AGENTS.md ngắn gọn, dễ hiểu.
Sau đó commit thay đổi này.
Dùng khi muốn Codex có “luật làm việc” trong project.
Prompt đề xuất MemoryThói quen cá nhân
Hãy đề xuất những Memory nên lưu cho tôi khi làm việc với Codex.

Bối cảnh của tôi:
- Tôi là người non-tech
- Tôi muốn tạo web tool đơn giản
- Tôi thích Codex giải thích ngắn gọn bằng tiếng Việt
- Tôi muốn Codex tự xử lý code, build, Git nếu có thể
- Tôi chỉ muốn bị hỏi khi cần quyền, đăng nhập, push GitHub, tạo repo mới, hoặc quyết định sản phẩm

Hãy trả về:
- Danh sách Memory nên lưu
- Memory nào không nên lưu
- Câu lệnh/prompt để tôi báo Codex ghi nhớ
Lưu ý quan trọng: không lưu API key, token, mật khẩu vào Memory.
Prompt tạo skill ship-checkWorkflow dùng lại
Hãy tạo một skill repo-scoped tên ship-check cho project này.

Mục đích skill:
- Dùng trước khi kết thúc task hoặc trước khi push GitHub
- Kiểm tra Git status
- Xem file nào đã thay đổi
- Chạy build/test phù hợp nếu có
- Báo lỗi nếu build/test fail
- Gợi ý commit message rõ nghĩa
- Không push GitHub nếu tôi chưa yêu cầu

Yêu cầu:
- Tự tạo đúng cấu trúc skill phù hợp
- Viết SKILL.md ngắn gọn, dễ hiểu
- Sau khi tạo, giải thích cách dùng skill bằng 2 ví dụ prompt
- Commit skill này
Dùng để có một nghi thức kiểm tra trước khi giao bài.

Kết quả đúng sẽ trông như thế nào?

Project có file AGENTS.md

Mở project lên sẽ thấy một file nội quy rõ ràng, ngắn gọn, đúng cách bạn muốn Codex làm việc.

Có danh sách Memory nên lưu

Bạn biết điều nào nên ghi nhớ, điều nào không nên lưu để tránh lộ thông tin nhạy cảm.

Có workflow kiểm tra trước khi giao bài

Codex biết cách kiểm tra Git status, build/test và báo cáo trước khi bạn kết thúc task.

Nếu Codex không biết tạo skill ở đâu?

Không sao. Hãy yêu cầu Codex đọc lại project và giải thích “skill nên đặt ở đâu trong môi trường hiện tại”. Nếu vẫn chưa rõ, chỉ cần giữ AGENTS.md và Memory trước.

Bài tập tự làm sau buổi 3

Tạo thêm một skill nhỏ tên ui-review

Hãy nhờ Codex tạo một skill giúp kiểm tra giao diện trước khi public: chữ có dễ đọc không, nút có rõ không, mobile có vỡ layout không, và người non-tech có hiểu phải bấm gì không.

Checklist cuối buổi

  • Project có AGENTS.md.
  • Học viên biết Memory nên lưu gì và không nên lưu gì.
  • Có skill ship-check hoặc hiểu cách yêu cầu Codex tạo skill.
  • Học viên hiểu đây là cách làm Codex ngày càng “hợp gu” hơn.
